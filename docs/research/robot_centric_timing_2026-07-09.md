# 机器人本位时间律:路径/时间分解(第一性原理复盘,franco+claude 2026-07-09)

**动机(franco 原话要义)**:最终要的是普适 pipeline。上半身动作学习"哪里要平滑、怎么平滑"
不该拍脑袋;设计应以"机器人该怎么动"为出发点——比如用均匀加速度去达到触球所需速度;
达不到就用**更多时间**达到相同速度,而不是降速。这同样重写了变速算法:全片加减速会让
加速度跟着变,实际要适配的是**最终速度**,该调的是**加速时间**。

## 一、第一性原理:任务对机器人的真实约束是什么

1. 回球任务的唯一硬约束是**触球瞬间的状态**:拍点 p*、拍面 n*、拍速 v*(题库答案)。
2. 触球前的一切只受机器人自身约束:力矩限位(URDF effort)、速度限位、平衡(支撑/质心动力学)。
3. 人类视频的价值 = **协调性路径先验**(引拍-挥拍的关节协同、髋肩次序、挥拍形状)——
   它让 31 维探索不必从零发明"人样"动作;它**不是动力学规范**:人的时序绑定在人的
   质量/惯量/肌肉上,机器人既不需要也不应该复制。

**推论:参考 = 路径(path),不是轨迹(trajectory)。** 这就是机器人学里 path/trajectory
分解(TOPP 思想):保留视频的空间路径与经过次序,时间参数化由机器人自己解。

**修正(franco 2026-07-09:时间轴不是没用,要看清帮助是什么)**——视频时序含三层信息,
逐层定去留:
1. **发力顺序**(髋→肩→肘→腕的波次):活在**多关节路径曲线本身**里——31 维联合路径 q(s)
   天然编码"谁先动谁后动",任何单调时间律都不破坏它。✅ 自动保留。
2. **节奏形状**(归一化的路径速度剖面 ṡ(s)/max:run-up 缓、鞭打段陡):这是人的力量传递
   策略,**可能**是有用先验——它该以"保形缩放"的方式保留(形状不动,幅度/总时长缩放到
   机器人预算),而不是逐帧照抄绝对值。
3. **绝对时间刻度与幅值**(多快、多猛):这是人的肉体常数,机器人本位重解。❌ 不抄。
第 2 层是真正的开放问题——**A/B 消融正是它的分解实验**:A(v5hLt)=保形缩放(节奏形状
保留),B(v5syn)=完全合成(匀加速,只保路径+触球速度)。若 A>B ⇒ 节奏模板有信息,
普适管线保留"保形缩放"步;若 B≥A ⇒ 连节奏都可合成,管线更简。候补 C(混合):鞭打段
(触球前 ~0.2-0.3s)保形、run-up 合成——若 A/B 各有胜场再上。
4. **目标速度**(触球帧拍速):双重角色——题库无特殊要求时的默认 v*;以及答案合理性
   先验(答案要求 3× 视频速度时应触发接口守卫警觉)。

## 二、时间律合成(替代一切"时间维平滑/重定时"补丁)

给定:路径 q(s)(上半身,来自视频)、触球点 s*、答案速度 v*、预警时间 T_avail。
解:单调时间映射 s(t),满足——

- 边界:ready 静止起步 → s* 处路径速度使拍速 = v*(时刻对齐击球倒计时)→ 收拍减速回 ready;
- 剖面:**匀加速**(= 最小峰值加速度的解)或最小 jerk;
- 预算:逐关节 |q̇| ≤ URDF 速度限位×余量,|q̈| ≤ 加速度预算
  (v1 = v4 实证包络×1.5——v4 是已证可执行且可学的动作,它的加速度包络就是"机器人做得到"
  的实证下界;v2 = 逆动力学 τ=M(q)q̈+h(q,q̇) 对 effort 限位留余量,URDF 惯量齐备可算);
- **不可达处理:延长加速时间**(提前起拍、拉长 run-up,必要时在 ready 段等待更少),
  永不降低 v*;若 T_avail 内无解 ⇒ 该题对该 ready 态不可行 ⇒ **回灌题库接口守卫**
  (阶段 2"接口能接的题"因此有了精确定义:时间律有解)。

**连带重写 R14(变速)**:变速的正确语义 = 换一个 v* 重解时间律(改变的是加速时间),
而不是全片时间缩放(那会让 a ∝ 缩放² 全程改变——优化了错误的量)。

**平滑问题就地消解**:时间维平滑从此**构造性成立**(时间律是我们合成的,天生光滑);
需要处理的只剩**空间维去噪**——路径本身被重建噪声污染的地方(判定:路径曲率异常 ×
vitpose 置信度低),与"触球窗保护"无关(窗内窗外是时间概念,路径去噪是空间概念)。

## 四、普适 pipeline 蓝图(终态;逐 clip 手术是过渡补丁)

```
视频 → GVHMR/GMR(帧0 warm-up)→ 上半身路径提取(+空间去噪,曲率×置信度判定)
    → 下半身任务驱动(站位/蹲深 = 来球函数;不从视频抄)
    → 逐题时间律合成(答案态为边界条件;预算=机器人模型)
    → 模型级可行性筛(判炸器 L0 + 逆动力学余量)→ tracker 过滤 → 训练
```

对照现有补丁的定位:warm-up=修路径(保留);腿移植 v5hL=下半身任务驱动的资产级近似

作对照臂);speed_scale R14=被"换 v* 重解"取代(旗标留作 legacy)。

## 七、可执行性的真约束与有效算法(franco 2026-07-09 晚二问:力矩才是上限?MuJoCo 按原动作测?)

**结论:是。物理上限=①逐关节力矩 τ_max(URDF 有,6-320 Nm 差 50 倍)+②地面接触可行性
(支撑脚只能推不能拉、CoP 在支撑面内、切向在摩擦锥内——"蹬地窗滑脚"就是违反这条:参考
要求地面提供做不到的力);"加速度上限"只是 τ/瞬时惯量的影子,逐关节且随姿态变,不该当
第一性常数用。**

**三层判定(便宜→贵,MuJoCo 全做得出)**:
- **A 层·逆动力学筛(mj_inverse,毫秒级/clip)**:对参考轨迹逐帧算所需广义力——
  ①执行关节:|τ_req| vs τ_max 余量(任何控制器的**上界判定**:超了=谁也做不到);
  ②浮动基座 6 维残差=所需地面外力 → 立力≥0 / CoP∈支撑面 / 摩擦锥三查。
- **B 层·PD 重放(分钟级/clip;判炸器 L1 补齐)**:厂商 MJCF+固件 PD 增益,q_des=参考
  原样喂,从参考初态起播——量跟踪误差/力矩饱和占空比/摔倒/脚滑。**现实控制器的下界判定**
  (增益有限、会饱和;聪明策略能做得更好,但 PD 都能跟的一定可行)。
- **C 层·tracker 预跑**(已立项 SMASH 式):学出来的策略=最接近真实可达集(会预倾借力)。

**时间律 v2 = TOPP**:沿路径逐点,q̈ = q′(s)·s̈ + q″(s)·ṡ² 使 τ 对 s̈ **仿射** →
每点解一个线性区间 τ_min ≤ M(q)q̈+h(q,q̇) ≤ τ_max ⇒ s̈∈[L(s,ṡ),U(s,ṡ)],再加接触可行性
对 s̈ 的约束——经典 TOPP 结构,逐点闭式解。**预算从"拍脑袋常数"变成逆动力学逐点解**,
"上限是多少"的最终答案=TOPP 给出的最短 T_a 本身。
**标定验证**:A 层先对剂量曲线已知结局回测(v4rg 应全过;R9e 的轨迹应过、R9d 的应在
窗内报违规)——oracle 预测顺序与实测摔率顺序一致才算校准。

## 八、TOPP 边界条件与消融换轴(franco 2026-07-10 晨二问)

时刻约束**:从 ready(s=0, ṡ=0)正向、从触球态(s*, ṡ*)反向,各自在逐点可行区间

决定**——答案方向与 clip 切向不合时,归适配器的拍面/路径 morph 轴管,不归时间律。
