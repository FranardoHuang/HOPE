## 1) Ball FLIGHT model (p.7, Methods "Ball aerodynamics", eq. 1)
- m·v̇ = f_d + f_M + f_g = −(1/2)·c_d·ρ_air·r²π·‖v‖v − c_M·ρ_air·(4/3)·r³π·(v × ω) + m·g
- Constants: ρ_air = 1.204 kg/m³, m = 2.7e-3 kg, r = 0.02 m, c_d = 0.55 (CONSTANT — no Reynolds dependence), g = [0,0,−9.81]ᵀ (p.7).
- Magnus coefficient is NOT constant (explicitly contrasted with base model ref. 49, Nakashima et al. ROBIO 2011): c_M = 0.1·‖v‖/(r‖ω‖) − 0.001 (verified from rendered page 7 image; text extraction garbles the fraction). I.e. c_M is a function of inverse spin parameter S = r‖ω‖/‖v‖.
- Algebraic consequence (my derivation, not stated in paper): substituting gives ‖f_M‖ = (4/3)πρ_air r²‖v‖²·sinθ·(0.1 − 0.001·S); in conventional lift-coefficient terms C_L = (8/3)·c_M·S = 0.267 − 0.00267·S ≈ constant ≈ 0.26. So Magnus force magnitude is essentially spin-magnitude-SATURATED — spin sets only the axis/direction.
- ω assumed constant over short flight intervals (no spin decay in flight) (p.7).
- Integration scheme: NOT stated anywhere in the main paper or Methods (grep for Euler/Runge/timestep/engine: no hits). Simulator engine not named ("custom physics models", Fig. 1 caption, p.2).
- The same aerodynamics model is reused inside the perception loop to lead the GCS mirrors ("system delay compensated by predicting the ball trajectory using the ball aerodynamics", p.7) and as the online "ball flight predictor" for closed-loop serves (p.10).

## 2) Ball–TABLE contact (p.7, eqs. 2–6)
- Instantaneous point-contact impulse model from ref. 49, "enhanced" with a velocity-dependent restitution: ε_table(v_z⁻) = 0.98 − 0.02·v_z⁻, and μ = 0.25 (dynamic friction), both "from experimental data" (p.7; no further ID detail). Note: for ε<1 the formula requires v_z⁻ interpreted as impact-speed magnitude; the paper prints it with the superscript-minus sign convention and does not resolve the sign explicitly.
- Linear pre→post maps: v⁺ = C_v,v·v⁻ + C_v,ω·ω⁻ ; ω⁺ = C_ω,v·v⁻ + C_ω,ω·ω⁻ (eqs. 2–3) with
  C_v,v = diag(1−α, 1−α, −ε_table); C_v,ω = [[0, αr, 0], [−αr, 0, 0], [0,0,0]]; C_ω,v = [[0, −3α/2r, 0], [3α/2r, 0, 0], [0,0,0]]; C_ω,ω = diag(1−3α/2, 1−3α/2, 1).
- α switches contact type (eq. 4): sliding (ν_s > 0): α = μ(1+ε_table)·v_z⁻/‖v_T‖; rolling (ν_s ≤ 0): α = 2/5. ν_s = 1 − (5/2)·μ(1+ε_table)·v_z⁻/‖v_T‖ (eq. 5). v_T = [v_x⁻ − rω_y⁻, v_y⁻ + rω_x⁻, 0]ᵀ = contact-point tangential velocity (eq. 6).
- My note: α_roll = 2/5 = (I/mr²)/(1+I/mr²) with I = (2/3)mr² — consistent with hollow-sphere inertia (same c=2/3 as HOPE v0 params.py).

## 3) Ball–RACKET contact (p.7 eqs. 7–8, p.8 matrices)
- Same linear impulse structure, rotated into racket frame R (racket-local → global): v⁺ = Rᵀ·C^racket_v,v·R·(v⁻ − v_racket) + Rᵀ·C^racket_v,ω·R·ω⁻ + v_racket ; ω⁺ = Rᵀ·C^racket_ω,v·R·v⁻ + Rᵀ·C^racket_ω,ω·R·ω⁻ (eqs. 7–8). Racket enters ONLY via orientation R and linear velocity at impact v_racket (racket angular velocity absent).
- Matrices (p.8): C_v,v = diag(1−k, 1−k, −ε_racket); C_v,ω = [[0, kr, 0], [−kr,0,0],[0,0,0]]; C_ω,v = [[0,−3k/2r,0],[3k/2r,0,0],[0,0,0]]; C_ω,ω = diag(1−3k/2, 1−3k/2, 1). k = "a coefficient relating tangential quantities" — NO value given in the main paper, and NO sliding/rolling switch (unlike the table model: k is a single constant where the table uses α(v⁻,ω⁻)).
- Two extensions over ref. 49 "to handle the wide ranges of linear and angular velocities encountered in professional-level table tennis" (p.7): (1) velocity-dependent restitution ε_racket = γ₁·e^{γ₂|v_z⁻′|}, function of normal RELATIVE velocity v_z⁻′, coefficients γ₁, γ₂ "fitted on data collected from games" (values not given); (2) a residual-correction neural network — "a small multilayer perceptron trained on game data" that "corrects both velocity and angular velocity error by 4% on average" (p.8).
- No explicit rubber/compression/contact-time model; rubber physics (Butterfly Dignics 05 2.1 mm on VICTAS ZX-GEAR OUT blade, p.3) is lumped into ε_racket, k and the residual MLP.

## 4) Parameter identification & validation data
- Ball position: 9 APS cameras (Sony IMX273), 200 Hz hardware-synced trigger, 1440×1080, FPGA 2D detection, 3.0 mm 3D error, 10.2 ms latency (p.2, p.7).
- Ball spin: 3 gaze-control systems — event camera (Sony IMX636) + galvo pan/tilt mirrors + telephoto tunable lens; CNN (low-latency) + contrast maximization CMax (accurate, slower); output 400–700 Hz; average spin measurement error 24.8 rad/s (~4 rev/s) (p.2, p.7). Spin uncertainty rises when the ball logo is invisible → 3 multi-view GCS fused by uncertainty (p.7).
- Fitting method: NOT described beyond "from experimental data" (table, p.7) and "fitted … on data collected from games" (racket, p.8). No fitting objective, no dataset size, no explicit speed/spin range of the ID data given in the main paper.
- Regime implicitly covered (match/game data): ball speeds to ~20 m/s, spin to ~1000 rad/s in pro play (p.1); observed maxima: Ace shots 16.4 m/s / 600 rad/s, returned opponent shots 19.6 m/s / 867 rad/s (p.4, Fig. 3e,f).
- Model prediction accuracy: the ONLY accuracy number in the main paper is the residual MLP's "4% on average" correction of racket-contact velocity/spin error (p.8). NO landing-position error, NO trajectory-prediction error over any horizon, NO spin-prediction error is reported in main text or Methods (presumably in Supplementary Information, not in this PDF).
- Implicit end-to-end validation = match results: 3/5 match wins vs elite players, >75% return rate up to 450 rad/s incoming spin, consistent returns to 14 m/s (pp.2, 4, Fig. 3a,c,d).

## 5) Use in training / sim2real (pp.2, 8–9, Fig. 1)
- Training is 100% in simulation (SAC, asynchronous parallel collection; asymmetric actor–critic: critic gets ground-truth sim ball state, actor gets history of N noisy simulated sensor measurements; auxiliary loss reconstructing true ball state from the actor's ball-state embedding) (pp.2, 9). Zero-shot transfer explicitly claimed (p.5 conclusion: "zero-shot transfer of policies trained in simulation").
- Sensor model in sim (p.8): APS — uniform latency, zero-mean Gaussian noise, fixed-probability dropout; spin sensor — same plus extra dropout immediately after racket contact (GCS tracking loss), plus separate Gaussians for precision (noise) and accuracy (bias) on spin magnitude and axis, with bias resampled once per contact event (mimics GCS reinitialization).
- Physics domain randomization (p.8): AFTER TABLE CONTACT ONLY — each Cartesian component of ball linear and angular velocity independently perturbed with zero-mean Gaussians. (No randomization of c_d/c_M/ε/μ mentioned.)
- Rewards (p.8, eq. 10): terminal-state-only; three cases R_miss / R_hit^¬return / R_hit^return. Skill-parameterized policies: R_hit^return conditioned on y_desired (desired landing y-position) and w_reward=[w_p, w_s]; w_p weights a distance-to-y_desired landing reward; w_s weights "a term proportional to the angular velocity in the y-axis of the ball frame on landing" → aiming, topspin, backspin skills. So the physics model's landing-position and landing-spin predictions are exactly what the reward reads out.
- RL plumbing that leans on the ball model: KDE initial ball-state distributions (synthetic + human data, serve:return sampled 3:7) (p.8); event-table replay stratification including high-top-spin/back-spin return events; hindsight relabeling of y_desired to the achieved landing position (p.9).
- Serves: strike motion optimized offline by genetic algorithm in sim on fitness over ball velocity, spin, landing position (pp.3, 9); real-robot gate: ≥20 open-loop repeats, ≤5% failure to enter library; closed-loop variant updates parameters online from the ball flight predictor (p.10). This is the one place where sim physics is explicitly cross-checked per-behaviour on hardware.
- Robot side of sim2real: joints as decoupled delayed LTI systems, parameters identified from recorded data (eq. 9, p.8); 1 ms actuator sync, <5 ms position-tracking delay, hardware clock shared with perception "essential for reducing the gap between simulation and reality" (p.3).

## 6) Low-speed validity / limits / failure cases
- NO explicit low-speed discussion anywhere. The model is motivated by and fitted to the professional regime ("wide ranges … encountered in professional-level table tennis", p.7).
- Net contact is implicitly NOT modelled: net-bounce rallies are showcased as "situations that are both rare and hard to model in simulation" handled by policy reactivity, not physics (p.5, Fig. 4).
- Known sensor failure mode: spin unobservable when logo hidden; spin tracking lost around racket contact (pp.7, 8).
- Physics perturbations concentrated after table contact (p.8) is an implicit admission that the bounce model is the least-trusted component.

## JUDGMENT — transfer to HOPE's low-speed amateur setting (2–8 m/s, ~60–380 rad/s, S = rω/v ≈ 0.15–1.2+)
Transfers directly:
- Table bounce model (eqs. 2–6): principled sliding/rolling impulse map, hollow-sphere-consistent (α_roll=2/5 matches v0's c=2/3 inertia), only 2 scalars (μ=0.25, ε(v_z)=0.98−0.02v_z). Velocity-dependent restitution is cheap and their values are a good seed; low-speed impacts (v_z ≈ 2–4 m/s → ε ≈ 0.90–0.94) sit INSIDE the plausible fit range, so this is interpolation, not extrapolation. This is more principled than v0's a_t + b_t·cosθ tangential heuristic and worth adopting.
- Racket linear impulse structure (eqs. 7–8): only needs racket pose R + linear velocity at impact — exactly what a ChingMu rigid body on the racket provides; racket angular velocity is deliberately ignored, which simplifies our data needs.
- Training-side recipe: terminal-state reward with y_desired landing distance + landing-spin term (eq. 10) is precisely HOPE's "(a) land reliably, (b) produce spin" goal; asymmetric actor–critic with sensor-noise/latency/dropout modelling and post-bounce Gaussian velocity perturbation are directly reusable and match the VRPN 300 Hz position-only deployment reality (actor sees noisy positions; critic can see sim-true spin).
- Drag: constant c_d=0.55 ⇒ k_d = c_d·ρ·πr²/(2m) ≈ 0.154 m⁻¹ (my computation) — same functional form as v0's constant k_d; Re for a TT ball only spans ~5e3–5e4 across 2–20 m/s, so a constant c_d is defensible at low speed too (fit the value from our mocap, don't trust 0.55 blindly).
Extrapolations / do NOT copy blindly:
- Magnus form c_M = 0.1·v/(rω) − 0.001 is a SATURATED-lift model (C_L ≈ 0.26 independent of spin magnitude). At high spin parameter (pro play, S ≳ 0.5) that is fine; at our low-spin end (e.g. 8 m/s, 63 rad/s → S ≈ 0.16) it predicts full Magnus force where real lift is roughly linear in S — likely 2–3× overprediction. v0's constant-k_m form (F_M ∝ ω×v) is the opposite limit (correct as S→0, overpredicts at high S). The low-speed mocap fit should decide between them or fit C_L(S); this is the single biggest physics divergence between Ace and v0.
- ε_racket = γ₁e^{γ₂|v_z′|}: form transfers, but γ₁, γ₂ were fitted on pro-speed game impacts and are unpublished — must be re-fit from the venue's low-speed racket+ball rigid-body data.
- Residual-correction MLP (4% gain): needs large volumes of in-distribution contact data; low value for HOPE now — the analytic model plus per-venue re-fit should come first.
- Missing from the paper entirely (must be sourced elsewhere or chosen ourselves): integration scheme, sim timestep/engine, tangential racket coefficient k, fitting methodology, and any trajectory/landing prediction-error benchmark. Anyone claiming "Ace validated X cm landing error" is citing the Supplementary Information or nothing — the main paper contains no such number.
- Base reference for both contact models is Nakashima et al., ROBIO 2011 (ref. 49, p.10) — worth pulling as the primary source for derivations and for the table-model sign conventions (the printed ε_table formula has an unresolved v_z sign convention).
