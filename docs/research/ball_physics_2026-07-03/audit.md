## 2) physics/ equations & assumptions (FACTS)

- `$TT/physics/flight.py:23-29` — `flight_accel`: a = (0,0,−g) − k_d|v|v + k_m(ω×v). ω is PHYSICAL spin, held **constant during flight — no aero spin decay, no aero torque** (module docstring lines 4–6; ball.py:71-73 confirms zero torque + angular_damping=0). `rk4_step` (lines 32–49): classic RK4 on v; p advanced with RK4-weighted velocity samples (line 48), matching the Record oracle `simulator.rk4`.
- `$TT/physics/spin_contact.py:37-81` — one impulse model for BOTH table and paddle: n oriented so incoming relative velocity approaches face (`orient_normal`, flip where (v−−v_r)·n>0, lines 37–44); u = v− + ω−×(−R n) − v_r; u_n = u·n; u_t = u − u_n n; cosθ = |u_n|/hypot(|u_t|,u_n) (line 67); s = clip((a_t + b_t·cosθ)|u_t|, 0, μ_safety(1+e_eff)|u_n|) (lines 68–70 — Coulomb cap applied as a hard min on the tangential impulse magnitude, floor at 0); Δv_t = −s·û_t; Δv_n = −(1+e_eff)u_n n; Δω = −(1/(cR))(n×Δv_t) (line 77). **e_eff is a constant scalar** — no velocity/angle dependence of normal restitution. v_r is an input meant to be "contact-point velocity" (docstring line 20).
- `$TT/physics/landing.py:42-132` — `predict_landing`: forward Euler-of-RK4 loop (dt=1e-3, max_time=2.0 s), detects first **descending** crossing of z=contact_z with v_z<0, refines by 24-iter bisection on the sub-step fraction (lines 96–110); independently tracks the forward crossing of x=net_x and reports ball-centre height there (net_z/net_valid, lines 77–90). Returns xy, valid, in_bounds, on_opponent (x>net_x), t_flight. **Flies straight through the net collider** (acknowledged in rewards.py:50-53). Vectorized over envs; landed envs frozen.
- `$TT/physics/params.py` — frozen dataclasses; YAML resolved by `$HOPE_BALL_PHYSICS_YAML` or upward search for `configs/ball_physics.yaml` (lines 68–84); lru_cached loader (125–128). Pure torch+PyYAML, no Isaac imports.
- C++ mirror: `agi/.../ball/ball_dynamics.{h,cc}` with **hard-coded defaults equal to the YAML** (ball_dynamics.h:45-60) and gtest goldens (ball_dynamics_test.cc: vertical drop rebounds at exactly 0.908·v, grippy tangential/spin goldens, PredictLanding golden 2.404731 — fixed in temp commit after the k_m recal).

- **Every fitted constant is rig- and ball-specific and none was fit at this venue or with ChingMu/Avatar Pro.** k_d is explicitly a hand-picked compromise (0.107–0.136 spread ≈ ±12%); k_m CI is ±17%; table e_eff/a_t came from a different table. For a team-validated v1, port/vendor the fit + oracle (or at least pin fit residuals as repo tests with committed reference trajectories, like the deleted calib_csv but curated).

JUDGMENT — missing / wrong pieces to fix before trusting sim results:
1. **Paddle v_r omits racket angular velocity**: env.py:174/187 passes `body_lin_vel_w` of the racket body as v_r, but spin_contact expects the **contact-point** velocity (spin_contact.py docstring line 20). A swinging racket rotating about the wrist has ω_racket×r contributions of order 1–3 m/s at the face — this materially changes imparted spin. Must add ω×(contact_offset) or fit the paddle model in a frame that absorbs it.
2. **Paddle contact point = body origin, radius 7.5 cm sphere** — no face geometry, no offset of the contact normal point; edge hits and face-position-dependent normals are unmodeled (env.py:37-39,178-184).
3. **No spin decay in flight** and no aero torque (flight.py docstring; ball.py:71-73) — acceptable at low spin, but should be checked against the new spin-tracked data since it's now measurable.
4. **In-sim verification of the callback-write ordering** (README limitation #1) has never been done; if PhysX integrates before the velocity write lands, the realized e_n ≠ 0.908. This is the single cheapest high-value check (vertical-drop test, few minutes on the RunPod).
5. **Landing predictor ignores the net and second bounces** — fine for rewards (gated), but don't reuse it as a "trajectory validation" tool against mocap without adding the bounce chain (the C++ `Simulate` has a bounce state machine; the torch side does not).
6. **Table μ cap disabled (μ_safety=2.0)**: valid only in the grip regime actually sampled; shallow-angle/high-spin serves in sim can produce unphysical tangential impulses. Refit or bound with a measured friction coefficient from the new data.
7. **hope_planner / deploy chain still on the old k=0.5 s/m model** — unit-incompatible (s/m vs 1/m) with the YAML; any reward-from-prediction work that must match deployment needs this reconciled.
8. The env's policy obs (ball_pos_b/vel_b) assumes velocity is observable; the real VRPN stream is **position-only at 300 Hz** — a deploy-parity ball obs will need a finite-difference/filter contract, which nothing on this branch defines.
